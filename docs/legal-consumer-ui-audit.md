## 主要问题与整改

| 优先级 | 原问题 | 用户影响 | 本次整改 |
| --- | --- | --- | --- |
| 高 | 首屏像聊天框，上传只是角落的小按钮 | 不清楚先提问还是先上传 | 明确的上传与拖拽入口、文件限制、处理说明；关注点和模型为可选偏好 |
| 高 | 脱敏、主体、交易背景、模型和授权集中堆放 | 不知道当前阶段、还差什么 | 检查隐私→确认立场→逐条审查→核验与导出；必填与可选分层；禁用原因就地解释 |
| 高 | 过程记录和交易摘要早于主要意见 | 找不到最值得处理的风险 | 概览之后优先展示意见；协作过程和检索资料在后；移除遮挡内容的悬浮导出面板 |
| 高 | 手机上传后自动展开正文 | 后续设置被遮住 | 手机保留在操作工作区；正文显式切换；桌面保留并排对照 |
| 高 | 禁用按钮缺少原因 | 无法判断网络、权限或输入问题 | 开始审查、采纳与导出均解释条件，保留后台校验 |
| 中 | 小字号、低对比、相近卡片层级 | 长文难读，主次不分 | 法务模块独立色彩与排版；深色导航、浅色工作区；统一表单和按钮 |
| 中 | 浏览器 confirm 承担关键授权 | 信息难读，取消行为不明确 | 上传、脱敏、修订导出使用带标题的原生模态框，支持取消、Escape、Tab 焦点约束与返回 |
| 中 | 缺少意见搜索和待办筛选 | 意见多时难逐项处理 | 搜索、待处理／待核实／已纳入修订筛选；稳定排序；概览可直接定位 |
| 中 | 主体绑定需要手工重输引用 | 易复制错字或代表错方 | 从所选原文提供可点击片段，仍由用户明确选择，不替用户推断立场 |
| 中 | 空态、错误态缺少恢复路径 | 容易反复刷新或重复操作 | 工作空间重试、模型重读、筛选清除、历史搜索无结果说明 |
| 中 | 移动导航焦点与隐藏状态不同步 | 键盘焦点丢失或进入背景 | 修正显示时机、焦点返回与限制，背景 inert，支持减少动画偏好 |
| 中 | 单一渲染函数混合布局和筛选业务 | 小改动容易影响其他流程 | 提取 Welcome、ConfirmDialog、WorkflowSteps、ReviewOverview 和可测试的 deskLogic |

## 保留的不变量

原件只在明确确认上传授权后发送后端，此时不调用模型。模型外发仍需脱敏确认、主体、角色、模型和独立授权；相关设置变化后重置授权。

合同场景与角色仍由后端版本化目录提供；模型仍来自 YData 合并目录，没有把密钥放进前端。缺乏依据、缺少事实或被复核否定的意见不会被包装成可靠结论。没有可采纳意见不等于没有风险。

人工修改、决定版本、修订组合核验、最终确认和 DOCX 原生修订保留。TXT 明确标为文字修改稿，不再描述为 Word 修订文件。首页、研究 Agent 和后端权限不在此次改动范围内。
