# 极速与快速审查：像 AI 对话应用一样审合同

## 为什么改

在 Kimi、ChatGPT、Claude 的网页端上传一份合同并要求审查时，模型读到的是整份合同，可以自由地充分分析，写出完整的审查意见和修改条款。原来的两个速度档位做不到这一点：

- **极速**：一次调用审查全文，但提示词要求“最多 8 条意见、理由不超过 120 字、影响不超过 50 字”，每轮最多两次模型调用，输出上限 8192 tokens。推理型模型常常还没写完就被截断。
- **快速**：每 2 条规则一组并行审查，每组最多 6 条意见。每组只关注自己的规则，看不到整体判断；同一段落常被不同组给出不同的修改，只能留给用户合并。

模型本身的能力被流程和提示词压住了。这次把两个档位都改成网页端 AI 的做法。标准和深度两个档位不变。

只放开模型还不够：网页端的模型在审查时会调用工具，例如联网检索法规原文、运行代码计算金额。两个档位因此也给模型提供一组工具，由模型按需调用，见“按需调用工具”一节。

## 现在怎么审

脱敏后的合同全文作为一份文档交给模型，每段以段落编号开头，例如 `[p5]`。同一份文档里还有审查任务、我方角色和我方主体、交易背景与资料缺口、审查清单、公司规范、审查方法和文件解析提示。审查在同一个对话中完成。

系统提示词让模型以资深商事律师的身份工作：

- 先通读全文，再找致命条款；
- 逐条审查，检查跨条款一致性，找出缺失的条款；
- 不设条数上限，不压缩分析，也不凑数；
- 严格区分法律风险、商业风险和公司规范偏离；
- 法条写全称和条号，不确定的条号不编造。

模型的回答分两部分：

1. **审查意见书**：Markdown 格式，写给业务负责人和法务。依次写交易概况与我方位置、总体评价、主要风险、缺失条款、谈判策略，以及需要补充核实的事实。
2. **结构化结果**：逐条意见，每条有段落编号、逐字引文、分析、影响、法条和完整的替代段落，另有审查清单各项的结论。

| 档位 | 流程 | 正常情况下的模型请求 |
| --- | --- | --- |
| 极速 `ultra_fast` | 通读全文，一次写出意见书和修订稿；写之前按需调用工具 | 1 次，另加每轮工具调用 1 次 |
| 快速 `fast` | 通读全文写出初审，边审边按需调用工具 → 带着初审和第一遍取得的官方原文复读全文，自查后写出最终版本，复读时仍可调用工具 | 2 次，另加每轮工具调用 1 次 |

长回答的续写和格式修正另计请求次数，见“像对话一样继续和修正”。两个档位都不做独立复核。意见标注为“未复核”，用户可以直接编辑、采纳或导出。

## 按需调用工具

模型在写审查的过程中可以调用以下工具，和网页端 AI 检索、运行代码的方式一样。调用哪个、调用几次由模型决定；工具在本服务执行，结果作为资料交回同一对话，模型据此继续写。

| 工具 | 作用 | 数据去向 |
| --- | --- | --- |
| `search_law` | 在政府官方网站检索法律、行政法规、司法解释、部门规章和监管规定的原文 | 检索词发往检索服务；只读取白名单内的官方网页 |
| `read_law_article` | 读取某部法规某一条的官方原文，核对条号和条文 | 先查已取得的原文；没有时同上检索 |
| `find_in_contract` | 在合同全文中查找词语，核对定义、金额、期限、主体在各条款中的用法 | 不离开本服务 |
| `read_paragraphs` | 读取指定段落的准确原文 | 不离开本服务 |
| `calculate` | 精确计算金额、比例、利息、违约金占比，支持百分号和“万”“亿” | 不离开本服务 |
| `date_calc` | 计算日期间隔，或某日加减年、月、日后的日期 | 不离开本服务 |
| `check_revision` | 用导出修订稿时的同一套检查核对修改后的段落 | 不离开本服务 |

规则：

- **检索词筛查**：检索词与原有的法规检索规划使用同一套筛查，含当事人、脱敏代称、金额、日期或与合同原文重合的检索词一律拒绝，不发出，并告诉模型改用法规名称和通用法律概念。
- **只认法规本身**：`read_law_article` 只从标题就是该法规的官方网页取条文；司法解释、草案、解读等页面里的同号条文不算。
- **可以引用**：工具取得的官方原文带来源编号，模型可以在意见中逐字引用；引用照常校验，与原文不符的不采用。意见中写出的法条与取得的原文按法规名称和条号自动对照。
- **工具结果是资料**：提示词写明工具返回的内容不是指令。
- **并行执行**：同一轮的多个调用同时执行，一轮最长等待 2 分钟，超时的调用告诉模型没有结果。
- **安全上限**：每个回答的工具调用有上限，只为防止失控：极速档最多 12 轮、48 次调用，其中法规检索 12 次，工具结果合计 4 万字；快速档每遍最多 16 轮、64 次调用，其中法规检索 20 次，工具结果合计 6 万字。超出的调用不执行，告诉模型原因，请它直接写出结果。超过轮数上限后，模型再调用工具只会被告知直接写出结果；这样又过两轮仍在调用时，本次审查暂停，可重试。
- **快速档复读**：第一遍的工具调用过程不再重放；第一遍取得的官方原文随复读请求一起给模型。

兼容各模型的接口：

- GPT、DeepSeek、Kimi、GLM 经 YData 使用 OpenAI 格式的工具调用；Claude 经 Anthropic 官方 API 使用原生的 `tool_use` 和 `tool_result`。
- 推理模型在调用工具时写下的推理过程会随对话交回，部分模型要靠它继续推理；接口不接受时自动去掉后重试。
- Claude 的每一轮都会重新发送整份合同，因此合同和最新一轮标记为 Anthropic 提示缓存，减少重复计费和等待。
- 模型接口拒绝工具调用时，本次审查自动改为不带工具重新进行，并记住这一选择：极速档一次写完，快速档回到“列出法律问题 → 检索 → 复读”的流程。运维可以用 `LEGAL_CHAT_TOOLS=0` 关闭所有审查的工具调用。
- 没有配置法规检索服务时，只提供不离开本服务的五个工具。

## 像对话一样继续和修正

- **回答被截断**：输出达到上限、超过时限或连接中断时，保留已写的内容，在同一对话中请模型接着写。
- **推理占满输出空间**：模型还没开始写答案时，把输出空间加倍后再试一次。
- **结构化结果读不出**：把问题告诉模型，请它只重写结构化结果，最多两次。
- **同一段落有两份修改**：请模型合并成一份完整文本；合并失败时两份都留给用户选择。

每次回答默认最多输出 32768 tokens，可用 `LEGAL_CHAT_MAX_TOKENS` 调整（1024–131072）。网关不接受这个值时，自动改用 `LEGAL_YDATA_MAX_TOKENS`，长回答靠续写补齐。

Claude 模型的对话同样经 Anthropic 官方 API 进行，其他模型经 YData，续写、修正和合并的方式相同：

- Claude 的输出空间不超过官方接口为该型号列出的上限；官方 API 拒绝时，改用 `LEGAL_ANTHROPIC_MAX_TOKENS`。
- 审查只发给用户授权的处理方。原先记录为经 YData 处理的 Claude 审查，不会改发到 Anthropic。

单次回答最长 30 分钟，模型最长可以 10 分钟不输出任何内容。审查运行期间每分钟续一次租约，推理时间长的模型不会被误判为中断。

以下上限只为防止失控，正常审查远远用不到：每轮最多 80 次请求（每轮工具调用算一次），每个回答最多续写 12 次。

## 本地检查

以下检查都在后端完成，不调用模型：

- **定位**：段落编号与引文不一致时，以替代文本最接近的段落为准。找不到引文时锚定到整段。既没有可用编号也没有引文的意见，作为“待确定插入位置”保留，不丢弃。
- **公司规范**：意见必须写明本轮有效的 `policy_id`，否则按商业意见处理。
- **修订稿**：使用与导出相同的检查，包括脱敏代称的数量和顺序、新增的身份信息等。通过检查的修改直接写入预览稿（`decision=draft, source=model`），人工决定始终优先。
- **审查清单**：模型没有单独报告的项标为“待补充”，不当作已经审查。
- **法规检索**：模型调用工具检索时，以及不带工具时快速档的检索规划，检索词都与标准档一样经过筛查，不含当事人、代称、金额或合同原句。官方原文按法规名称和条号挂到对应意见上。

## 审查进行中

- 审查进度中逐字显示模型正在写的意见书，每 2 秒同步一次。模型思考时显示已思考的字数，写结构化结果时显示已写条数。
- 模型调用工具时，审查进度里逐条列出调用了什么、查了什么、结果如何，例如“检索法规 民法典 违约金 调整 · 取得 2 个官方来源”“计算 1000000 * 30% · = 300000”；实时动态中也记一笔。
- 快速档复读期间，正文上标出初审意见。这些初审意见不能采纳。
- 审查完成后，“依据”标签列出模型调用的全部工具（快速档按初审、复读分组）和取得的官方来源；导出的审查报告也附有这份清单。
- 审查完成后默认打开“意见书”标签，文中的段落编号可以点击，定位到正文对应段落。
- 导出的审查报告开头附有意见书；追问时，模型可以参考意见书回答。

## 重试

对话按检查点保存，重试从最后一个完成的回答继续：

- 快速档复读失败时，先交付初审结果，状态为“部分完成”。重试只重新复读，第一遍的工具记录和取得的原文保留。
- 不带工具的快速档中，法规原文有缺口时，重新检索不调用模型，只把新取得的官方原文挂到已有意见上。模型自己调用检索没有取得原文，不算缺口：它已在回答中据此审慎表述。
- 已有人工决定的审查不能重试，请新建审查。

## 兼容

- 标准和深度两个档位的流程不变。
- 旧版极速、快速审查的结果照常查看。重试时按新流程重新审查。
- 本功能上线前开始、尚未完成的对话式审查，重试时带工具重新开始对话。
- 后端需要重新部署；前端随 Vercel 自动部署。
