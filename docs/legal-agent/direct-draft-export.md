# 法务审查：直接出稿与用户决定导出

## 用户流程

极速和快速审查完成后，直接展示根据模型建议生成的修订稿。用户可以修改文字、确认某项修改或保留原文，也可以直接导出当前稿件。

- 待处理项为 0：点击导出即可下载。
- 仍有待处理项：显示数量，用户确认一次后下载。
- 模型未复核、表示不确定、持异议或组合核验未通过，都不否决用户的编辑和导出决定。
- 没有修改也能导出。DOCX 默认保留原生修订痕迹；用户可以明确选择纯文字稿。复杂 Word 结构无法安全回写时提示原因，绝不静默转换格式。

报告中的模型复核意见仍然保留。被复核模型否定的建议也保留原文和修改文字，便于用户比较判断。历史记录中已经被旧逻辑删除的建议不能自动恢复，仍可人工输入修订。

## 两个速度档位

| 档位 | 正常调用路径 | 结果 |
| --- | --- | --- |
| 极速 `ultra_fast` | 一次调用，读取完整合同、全部规则和公司规范，同时审查并生成替代段落 | 自动组装为可编辑草稿 |
| 快速 `fast` | 按检查范围并行调用，无独立复核、法规检索或额外组合检查 | 自动组装为可编辑草稿 |
| 标准、深度 | 保留现有检索、复核及协作流程 | 模型意见供用户参考，导出同样由用户决定 |

极速每次执行最多两次模型调用：正常一次，传输或结构化输出失败时最多恢复一次。不会为导出发起模型调用。完整合同超出输入预算时明确报错，不静默截断；候选定位无效或缺失覆盖结果时标记部分完成，保留可用稿件并允许重试。

自动稿使用 `decision=draft, source=model, manual=false`，不冒充用户已接受。重试可以重建这些自动稿；任何实际人工决定都受保护。自动稿和手工修改使用相同的文档校验。同段相互冲突的替代文字留待用户选择，不能随机拼入正文。

## API

审查结果新增：

```json
{
  "export_state": {
    "ready": true,
    "pending_count": 3,
    "selected_count": 2,
    "fingerprint": "<当前稿件的 SHA-256 指纹>",
    "confirmation_required": true
  }
}
```

`pending_count` 按唯一意见统计：尚未明确接受或保留原文的意见，包括模型生成的 draft。`accepted` 和 `draft` 都构成当前预览和导出的文本；未选择的修改不写入稿件。

`GET /legal/reviews/{id}/export?format=docx|txt|json`：

- 无待处理项可以直接下载。客户端仍传入预览时的 `fingerprint`，避免下载另一份已变动的稿件。
- 有待处理项时，确认请求附带 `confirmed=true&fingerprint=<预览指纹>`。
- 未确认返回 409，`detail.code=export_confirmation_required`，携带最新数量和指纹。
- 预览或确认过期返回 409，`detail.code=export_stale`。客户端更新当前稿，用户重新决定导出。
- 原文档不可写入、段落定位或脱敏映射不一致等属于文件生成错误，单独说明原因。

`draft-check` 保留为显式请求的可选模型建议；`draft-approval` 为兼容接口，仅记录用户决定，不再要求模型核验通过。常规导出不调用这两个接口。

身份权限、事项权限、原文档版本、脱敏映射、段落定位、文件有效性以及生成期间的版本一致性校验继续执行。审计记录包含导出格式、稿件及文件指纹、剩余待处理数量和本次是否确认，不把导出解释为法律适用已经验证。

## 设计参考与验证

参考 [OpenCode Agent 配置](https://opencode.ai/docs/agents/) 的按任务配置能力与步数上限，以及 [Hermes 核心架构](https://hermes-agent.nousresearch.com/docs/developer-guide/architecture) 的模型主循环和按需工具。此处保留项目现有 Python/FastAPI 和 YData 适配，不引入整套新框架，也不声称复刻 Kimi 的内部实现。

回归重点：单次完整输入、有限重试、自动稿恢复与人工决定保护；未复核或存在模型异议时直接导出；待处理数量、一次确认与过期指纹；TXT/DOCX 含实际 draft 和 accepted 文本；零修改原件导出；中英文预览、编辑与下载流程。测试模型使用合成结果，不以这些测试宣称真实模型的法律准确率或生产耗时。
