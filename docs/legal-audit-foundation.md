# 法务审计整改：第一轮可靠性与修订交付

基线：`main@1c1b702bb3720a2dae9a2e08d625c1ac935771ed`。
本轮没有变更生产密钥、会员记录、部署地域、已有首页或研究 Agent。

## 这轮真正改变了什么

- F01：区间化身份识别保留角色与履行动词；覆盖审计中的公司名吞并甲乙方、联系人吞并义务和自然句人名反例。附原文/替代区间，增加仅编辑成员可用的真实原文对照和撤销过度脱敏。原件中的保留占位符拒绝解析，避免与系统映射冲突。
- F02（部分）：上传前明确原件先到后端，再解析/加密/脱敏；服务端要求本版本说明确认并保留记录。补充要求和公司规范共用一次脱敏，避免规范未经处理外发及不同规范代称碰撞。可配置 LEGAL_STORAGE_REGION 作为运营方声明，不把声明变成核验结果。
- F03：手工文本变化不能直接 accepted，只能 draft；代称顺序互换被确定性阻断。对实际选中的完整修改组合重新调用原模型复核，然后由用户确认精确组合。原件、角色、规则、候选意见、决定版本及最终文本进入指纹；任何决定变化使检查和确认失效。导出前后检查指纹，审计记录最终文本和文件哈希。
- F05（入口部分）：我方主体必须绑定本版本脱敏正文的一段逐字片段，不再只有采购方/供应方角色选择。模型接收绑定而非自动推断甲方等于我方。
- F09：已被复核否定的候选从高/中/低风险统计移除；待确认、已否定与有支持的风险分别显示。报告也标明状态，不以初审严重程度渲染被否定项。
- F10（状态部分）：追问携带候选复核、证据、人工决定与修订确认状态，不把草稿、被否定意见和已选建议表述成已签署事实。
- 发布门禁增加 audit_foundation_version=1 和 draft_release_version=1。保留后端先上线的要求，不能用新前端连接不支持新接口的生产后端。

## 当前不声称完成的能力

姓名识别仍是本地启发式，不是完备 NER 或匿名化证明；预览和人工检查不可取消。
未核实实际部署地域、供应商协议、留存/训练使用和转委托，不认证跨境合规。香港或国内型号也不是合规证据。
未实现完整交易事实表、法规效力/时间适用数据库、公司规范决策卡、多轮红线稿比对、企业权限审批、签后履约或真实法律准确率评测。
最终确认只是用户确认一份待审阅的修订副本，不代表有签署权限或企业已批准交易。模型组合核验仍可出错。

## 修订状态机

1. 通过候选复核的原始建议可选为 accepted；这只是选入修订集合。
2. 人工编辑必须显式保存为 draft，保留具体文本和决定版本，不继承旧文本的复核结论。
3. POST /legal/reviews/{rid}/draft-check：仅用原模型、原授权事项，比较原文和实际选中组合。每条修改唯一回执、全文一致性回执及缺口清单缺一不可。
4. 任一步缺失、冲突、上下文超限、权限撤销、租约超时或并发改稿，不发布可确认结果。
5. POST /legal/reviews/{rid}/draft-approval：用户提交精确指纹及明确确认，服务端 CAS 核对，再把 draft 转为选中修改并锁定组合。
6. DOCX/TXT 导出要求有效确认；导出生成后再次核对快照，防止竞态导出旧稿。JSON/Markdown 报告不受这个交付门禁限制。

检查请求有持久幂等编号、每用户/事项并发限制及一分钟内次数限制；不会重试到另一个模型或提供商。
新增检查记录仍通过现有 encrypt_json/decrypt_json 保存，不另存明文。

## 向后兼容和部署顺序

历史合同和报告保持可读。旧 redaction_version 或缺少 audit_foundation_version 的历史任务不能直接生成新的修订交付；需重新上传/确认脱敏并发起新审查，避免 silently 重映射已接受修改。
API upload 新增 original_upload_confirmed=true 和 upload_notice_version=original-upload-v1；新 review 要求 our_party.block_id/quote。

先部署后端，确认 /legal/version 两个新增标记；然后部署此版本前端。过渡期间旧前端的新上传会收到明确说明错误，不会绕过授权。此 PR 不自动改部署配置或生产数据。
