# 法务迭代二：交易背景与证据可靠性

基线：审计整改 PR #8；开始本轮时远端为 `50903a0`。
本轮在同一 PR 上完成后按用户授权合并 main；不更改密钥、会员、存储地域或原始合同数据。main 推送会触发现有部署工作流，是否发布成功须另看其结果。

## 实现

1. 修复中间提交留下的 Python 正则行被破坏、TypeScript 字面换行符导致的编译问题，以及前后端法律版本待核验状态口径不一致。
2. 交易阶段、附件声明、业务重点、金额和币种随审查快照冻结。金额按 Decimal/十进制字符串传递，不用 JS 浮点数中转，不把非法数变成未知值。新建、上传或打开另一份合同都重置表单，历史审查按其快照恢复。
3. `transaction_brief` 分开保存用户陈述、正文中明确的材料引用、未提供项和解析限制。所有标准/多 Agent 调用、最终修订核验、追问使用本轮快照。仅在相关段落依赖未确认材料时阻断其修订资格，不能靠模型漏填 missing_facts 绕过。用户声明附件齐全不是解析完整性证明；此轮没有跨文件附件自动匹配。
4. 法律来源增加页面类型初筛、页面记载的施行日期候选、检索状态面板。草案、解读和案例材料不能单独冒充正式法条支持法律意见。日期来自网页逐字片段，不自动选取某个日期为生效版本；版本仍是 needs_verification。
5. 公开主题检索使用与准入相同的官方域名范围；搜索空结果/失败时，可有限度实时读取相关的官方原文地址。只保存 URL 目录、不打包法律正文；可通过 `LEGAL_DIRECT_OFFICIAL_FALLBACK=false` 禁用。关闭检索提供方时不走旁路。每个页面仍执行 HTTPS、域名、重定向、公开地址、大小及正文检查；记录实际最终来源 URL。直连成功只证明取得来源，不证明其最新、完整或适用。
6. 条文按行首标题拆分，不把句中的“依据第某条”当作新条。超预算的单条规定不再截半作为证据。已有整条预算测试使用真实标题换行，另加句内引用和超长条文反例。
7. 审查报告携带交易背景、资料缺口与检索状态。未核验法律版本不计入“有依据的重点”数量，仍作为待处理意见保留。

## 验证和边界

`tests/test_legal_iteration2.py` 为合成安全/数据契约回归，不是真实法律评测。另有标准/多 Agent 消费验证、修订指纹失效测试、前端金额/状态测试，以及构建后的浏览器表单、展示和重置断言。

本地可运行独立核心回归；完整运行库的可用性受环境限制，全量后端与前端 typecheck/lint/unit/build/browser 以最终 SHA 的 GitHub CI 为准。没有真实客户合同或生产模型调用。

`python scripts/legal_retrieval_probe.py --require-source` 在没有来源时非零退出，供发布验收明确选用；默认 CI 模式仍输出非阻断诊断并保存实际结果。不能用 CI 绿色宣称真实检索成功。

## 发布

新增后端能力标记 `transaction_brief_version=1`、`evidence_screening_version=1`；前端生产发布门禁要求这两个标记以及第一轮全部标记。按原有顺序先部署后端再发布前端，不绕过门禁。主分支合并不代表部署已经完成。

仍未完成：独立核验实际地域与上游协议、法律法规版本沿革和适用性结论、公司规则决策卡、对方回稿比对、企业审批、专业标注的法律准确率基准。这轮没有把这些事项改成“已完成”。
